# F1.3 — Semantic Coverage, Preview Transcript, and Readiness Gate

**Requirement:** CUT-03
**Difficulty:** 7/10
**Layer:** Python / JSON validation
**Depends on:** F1.1, F1.2
**File ownership:** `helpers/semantic_qc.py`, `helpers/verify_edit_ready.py`, narrowly required transcript helpers, `tests/**`.

## Goal

Make the edit auditable by content and stop the normal workflow before XML when boundary/audio/semantic/preview-transcript evidence is missing, stale, or requires review.

## Required behavior

- `metadata.required_beats` is mandatory, including `[]`; validate each beat's `id`, `description`, and non-empty `evidence_any_of` alternatives. Ranges reference `beat_id`.
- Semantic QC writes `edit/edl_semantic_qc.json`, binds to EDL/transcript hashes, verifies evidence against transcript words selected by the actual ranges (never `quote`), and contains no Ticto/PF/PJ hardcoding.
- Preview transcription is mandatory in normal workflow. Bind the preview WAV SHA-256 and transcript hash in `edit/preview_transcript_qc.json`; make the transcript provider injectable/mocked for public tests, never call ElevenLabs in CI.
- Final content gate requires 100% required beats, phrase fuzzy score >= 0.85, expected-token recall >= 0.90, no recording cue, duplicate, or missing span of >=3 tokens.
- `helpers/verify_edit_ready.py` validates hashes/status/freshness across boundary, audio, semantic, and preview-transcript reports; 0 pass, 2 review, 1 fatal. Reports stale against EDL/WAV/transcripts are rejected.
- Do not modify the manual XML CLI behavior in this task.

## Validation

Public synthetic JSON/WAV fixtures only. Cover empty required beats, valid evidence, missing/stale report, missing beat, fuzzy/recall failures, recording cue/duplicate/missing-span failures, preview SHA mismatch, and a complete ready pass. Run pytest and helper `--help`; commit locally without push/merge.
