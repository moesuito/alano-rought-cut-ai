# Demonstração de produto

Use quando as falas apresentam produto, feature, workflow ou explicação orientada ao uso.

Estrutura comum: `PROBLEMA -> FEATURE -> DEMONSTRAÇÃO -> BENEFÍCIO -> CTA`.

Priorize o problema resolvido, passos ou demonstrações descritos na evidência, benefício em linguagem do usuário, prova verbalizada e próximo passo claro.

Exclua setup que atrasa o produto, descrições repetidas, espera narrada sem função, benefício vago e tangentes fora do fluxo.

Riscos de revisão: prometer uma ação visual que a transcrição não prova, manter feature sem problema ou cortar antes do benefício. O agente seleciona conteúdo; sincronização com UI exigirá evidência futura fora deste contrato.

Não force todos os beats quando a evidência não os sustenta.
